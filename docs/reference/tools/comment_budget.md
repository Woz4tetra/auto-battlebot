# Comment budget checker

`scripts/comment_budget.py` enforces the no-comments rule in `CLAUDE.md` ("Comments"). Every file
has a budget of 0 counted comment lines except the accepted rules in `.comment-baseline.json`:
invariants no test can prove, each approved by the user.

| File | Lines | Rule |
| --- | --- | --- |
| `src/runner.cpp` | 2 | `cancel_initialize()` overrides are async-signal-safe (one atomic store) |
| `src/rgbd_camera/video_encoder.cpp` | 3 | `stopping_` is set under the lock, or a frame races into the next file |
| `firmware/mr_stabs_mk2/include/wifi_manager.h` | 1 | `_state` is owned by the task, read by `snapshot()` under `_lock` |

## Commands

```bash
python3 scripts/comment_budget.py check            # fail on any file over budget
python3 scripts/comment_budget.py check --files f  # only the given paths
python3 scripts/comment_budget.py check --staged   # staged files (pre-commit hook)
python3 scripts/comment_budget.py ratchet          # lower budgets to current counts
python3 scripts/comment_budget.py report           # totals by dir and language, top 30 files
python3 scripts/comment_budget.py blocks --json    # every counted block: path, line range, text
```

`check` prints each offending file, its count, its budget, and the offending lines.

## What it scans

- Input is `git ls-files` minus an exclude list in the script: `data/`, `third_party/`,
  `firmware/BlHeli-Passthrough/`, `.pio/`, `node_modules/`, `.serena/`, and generated files
  (`web/**/protocol.ts`, `firmware/velocity_jig/include/splash_anim.h`, any file whose first 3 lines
  say `@generated`, `Generated by` or `Do not edit`).
- C, C++, TS, JS, `.ino`: a lexer that skips string, char and raw-string literals, then takes `//`
  and `/* */`. Each physical line of a block comment counts once.
- Python: `tokenize` for `#` comments, `ast` for module, class and function docstrings. A docstring
  of 2 or more lines counts its line count; a one-line docstring counts 0.
- Shell, TOML, CMake, `.ini`, YAML: `#` lines outside quoted strings.
- Markdown is not checked. Prose goes in `docs/`.

Each line is counted, an exempt directive (the table below), or a `DATASHEET:` line. A
malformed `DATASHEET:` line fails regardless of budget.

### Exempt forms and DATASHEET lines

Exempt forms count zero and carry no prose:

| Form | Constraint |
| --- | --- |
| `#!` shebang | First line only |
| `#pragma`, include guards | Preprocessor, not comments |
| `// NOLINT(check)`, `// NOLINTNEXTLINE(check)` | Check name required, no trailing prose |
| `# noqa: CODE`, `# type: ignore[code]` | Code required, no trailing prose |
| `// clang-format off` / `on`, `# fmt: off` / `on` / `skip` | Generated or table data only |
| `# -*- coding`, SPDX and license headers | First 5 lines only |
| `}  // namespace name` | clang-format writes these (`FixNamespaceComments`) |
| `/// <reference types="..." />` | TypeScript directive |

Files whose first 3 lines say `@generated`, `Generated by`, or `Do not edit` are skipped, as are
vendored code and `.serena/`.

`# noqa: E501 because the URL can't wrap` counts: the justification is prose.

`DATASHEET:` is the one prose exception. One line per fact, with the document, its revision, and a
locator (`table N`, `N.N.N`, `p. N`, `fig. N`). The checker fails a malformed one regardless of
budget. Bench measurements and anything learned by trial are not datasheet facts; they go in `docs/`.

```cpp
// DATASHEET: BNO055 rev 1.4, table 4-2: OPR_MODE NDOF = 0x0C
```

## Baseline and renames

- `.comment-baseline.json` is `{path: count}`. A file not listed has a budget of 0.
- A path that `git diff -M` pairs with a baselined path inherits its budget, so `git mv` keeps it.
- There is no `--allow` flag and no inline opt-out marker. Raising a budget means editing the
  baseline by hand, where it shows in the diff.

## The checker checks itself

- `SELF_PATHS` (`scripts/comment_budget.py`, `scripts/tests/test_comment_budget.py`,
  `scripts/git-hooks/pre-commit`) are scanned and can never get a baseline entry; `check` fails if
  one has. Lexer fixtures are string literals inside the test file, not loose files.
- `test_checker_files_are_scanned_and_unbudgeted` asserts those files are scanned, unbaselined, and
  pass `check --files`. `test_self_check_is_live` copies the script into a temp git repo, appends
  one `#` comment, and asserts `check` fails.
- Tests: `scripts/tests/test_comment_budget.py`.

## Wiring

- `scripts/lint` runs `check` in full and `--quick` modes, then `ratchet` unless `--dry-run`. It sets
  `core.hooksPath` to `scripts/git-hooks`, whose `pre-commit` runs `check --staged`.
- `.claude/settings.json` has a `PostToolUse` hook that runs `comment_budget.py hook`, which reads
  the edited path from the hook JSON on stdin and checks that file.

## Where the removed comments went

- Workaround reasons: a "Workarounds" section in the reference or setup doc for that subsystem
  (for example `docs/reference/recording/video_recording.md`, `docs/setup/zed_box_mini.md`,
  `docs/reference/robot_link/firmware_telemetry.md`). The open workarounds and their root-cause
  fixes are listed in `docs/plans/comment_purge_hack_ledger.md`.
- Config field meanings: `docs/reference/config/fields.md` and the per-tool config docs.
- Measurements and fitted-value provenance: dated docs under `docs/experiments/`.
